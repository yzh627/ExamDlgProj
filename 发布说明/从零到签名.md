# 从零到 SignPath：这份文档带你走完剩下的路

## 你现在的进度

```
✅ 代码已上 GitHub（81 个文件，github.com/yzh627/ExamDlgProj）
✅ CI 能自动构建出完整安装包（全绿）
✅ 私钥零暴露（本机只有 SSH 部署私钥，从未离开过本机）
⬜ 申请 SignPath 免费签名
⬜ 签名后重新发布
```

**代码层面已经全部完成。** 剩下的都需要你本人操作，因为涉及你的账号。

---

## 第 1 步：开 MFA（两处都要，必做）

SignPath 明确要求**所有相关账号都启用双因素认证**，缺一个会被拒。

### GitHub 侧

1. 点右上角头像 → **Settings**
2. 左侧最下面 → **Password and authentication**
3. 找到 **Two-factor authentication** → 点 **Enable**（推荐用验证器 App）
4. 按提示扫码 + 输入验证码完成

### SignPath 侧

等第 3 步注册 SignPath 账号时，它会要求你开 MFA，届时按提示做。

---

## 第 2 步：打个标签，产出第一个 Release

SignPath 要求"项目已有可签名的发布版本"，所以要先有 Release。

### 操作

1. 打开仓库 → 右侧 **Releases**
2. 右侧绿色按钮 **Create a new release**
3. 点 **Choose a tag** → 输入 `v1.0.0` → 点 **Create new tag on publish**
4. 填标题：`v1.0.0 首个版本`
5. 描述随便写两句（这个页面就是 SignPath 要求的"下载页"）
6. **不要勾** "Set as a pre-release"
7. 勾上 **"Create a full release"**
8. 点 **Publish release**

### 注意

- **这个 Release 里不需要手动上传文件** —— 构建产物在 Actions 里，发布时用命令取。
- 勾上 "Set as a pre-release" 也可以，SignPath 看重的是"有可签名的发布版本"。
- **不要手动上传安装程序**：手动上传的文件签名者会显示"未知"，而 SignPath 只签自己构建的产物。

## 第 3 步：申请 SignPath 免费签名

### 提交申请

打开 <https://signpath.org/apply>，填：

| 项 | 填什么 |
|---|---|
| 项目 URL | `https://github.com/yzh627/ExamDlgProj` |
| 许可证 | MIT（我们仓库根目录的 `LICENSE`） |
| 下载页 URL | `https://github.com/yzh627/ExamDlgProj/releases` |
| 项目简介 | 河北对口升学计算机程序设计练习系统。原生 Win32 + MFC，提交代码即自动判分，判题环境与省考场一致。MIT 许可。 |
| 维护者身份 | 你的 GitHub 用户名 `yzh627` |

### 等待审核

人工审核，**通常 1–3 个工作日**。

### 会发生什么

通过后你会得到一个 SignPath Organization。**签名者会显示为 "SignPath Foundation"，不是你的名字** —— 这是他们的机制：用自己的证书为项目背书。好处是证书有真实公信力。

## 第 4 步：配置 SignPath 后台

登录 <https://app.signpath.io>，做三件事：

### ① 添加可信构建系统（Trusted Build System）

项目设置 → **Trusted Build Systems** → 添加 **GitHub.com** → 授权你的仓库

SignPath 靠这个确认"产物确实是你们仓库的 CI 构建出来的"。

### ② 创建工件配置（Artifact Configuration）

指向 Actions 产出的 artifact：
- 名字：`unsigned-windows`
- 里面的文件：4 个 exe

⚠️ **GitHub 默认把 artifact 打成 zip**，SignPath 的工件配置要求**根元素就是 zip**，
不要额外嵌套一层文件夹。

### ③ 创建签名策略（Signing Policy）

通常命名为 `release-signing`，绑定 Foundation 证书。

---

## 第 5 步：把凭据填进 GitHub Secrets

仓库 → **Settings** → 左侧 **Secrets and variables** → **Actions** → **New repository secret**

| Name | 填什么 | 类型 |
|---|---|---|
| `SIGNPATH_API_TOKEN` | 后台 My Profile → API Tokens 创建，权限选 **Submitter** | Secret |
| `SIGNPATH_ORGANIZATION_ID` | 后台 URL 里那串 GUID | Variable |
| `SIGNPATH_PROJECT_SLUG` | 项目设置页 | Variable |
| `SIGNPATH_SIGNING_POLICY_SLUG` | 一般是 `release-signing` | Variable |

**填完不用手动跑**，下次推 `v*` 标签时会自动签名。

---

## 第 6 步：发一个带签名的版本

1. 本地打包后推送：双击 **`推送.bat`**
2. 打标签触发构建：

```bat
git tag v1.0.1
git push origin v1.0.1
```

（走 SSH 的话可能要写全 `git -c "core.sshCommand=ssh -F %USERPROFILE:\=/%/.ssh/config_examdlgproj" push origin v1.0.1`，
或者直接双击 `推送.bat` 后在 GitHub 上手动创建 tag。）

3. 去 Actions 看构建 → 应该有 `Sign with SignPath` 这一步显示成功
4. 下载产物：Actions 页面最下面 **Artifacts** → 下载 `windows-build`

## 怎么确认签上了

**在你自己电脑上验（最快）：**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_release_signing.ps1
```

4 个文件都该显示 `[通过] 签名状态 Valid` + `[通过] 含 RFC3161 时间戳`。

**看发布者名字：** 右键 exe → 属性 → 数字签名 → 应显示 `SignPath Foundation`。

## 如果还被 Windows 拦

签名有效 ≠ 一定不拦。Smart App Control 还要看云端信誉。

**看真实拦截原因**（这一步别跳过，能直接告诉你是不是签名的问题）：

```
事件查看器 → 应用程序和服务日志 → Microsoft → Windows → CodeIntegrity → Operational
```

- 事件 ID **3076** = 评估模式（本来会拦）
- 事件 ID **3077** = 强制模式（实际被拦了）

**新软件初期被拦是正常的** —— 信誉需要下载量积累，通常几百次下载后会好转。

**不要**用这些方式绕过（有害无益）：
- 关闭 SmartScreen / Defender / Smart App Control
- 加壳或使用"免杀"工具
- 购买来路不明的共享证书
- 要求学生手动"解除锁定"再运行
